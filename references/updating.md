# 使用前检查更新及故障处理

更新源固定为 `https://github.com/skyekkk/invoice-reimbursement` 的 `main`，只接受该仓库与安装时本机绑定。每次新报销运行 `python3 -B <技能目录>/scripts/sync_skill.py`，不是定时后台检查。推荐官方接口安装，保留生成的 `.skill-install.json`；Git安装保留 `.git`。仅手动解压ZIP或复制SKILL.md、缺安装记录时不具备更新机制。

## 官方接口安装方式

`scripts/github_snapshot.py --install <不存在的新目录>` 从官方API读取main提交与树，下载固定提交的完整包，逐文件核对Git blob摘要，拒绝不完整包、越界路径、链接与子模块。首次安装已有目录时保留原状，不覆盖。

后续 `sync_skill.py` 自动识别安装记录，联网读取main，比较上次提交是否仍为前序，并核对本地受管理文件摘要。相同提交仍需确认本地无改动，不能把改过的副本称为最新版。有更新时先完整备份，再在临时目录保留未管理本地文件、替换受管理文件，最后交换目录；交换失败会恢复原目录。新增远端路径碰到本地自有文件时停止。个人配置在外部，始终不随更新替换。

API限流、网络、目录权限或完整性校验失败时明确报告未完成，不静默执行旧规则。该模式无需Git与GitHub登录，仅需Python 3；更新不执行下载包里的程序。

备份路径按真实路径检查，不能经链接落入技能内部。若目录交换失败会尝试恢复；恢复也失败时返回`unavailable`，并保留`recovery`旧目录及`backup`备份位置，不清理可恢复资料。先恢复到返回的`path`并核验完整，再继续使用。

## Git安装方式

脚本每次实际 `git fetch` 再比较提交。主分支干净且远端可快进时，先把旧版工作文件复制到 `XDG_STATE_HOME/invoice-reimbursement/backups/`；无该环境变量时为 `~/.local/state/invoice-reimbursement/backups/`。备份含旧提交编号；不复制.git，不删除旧Git历史。全部Git调用（含fetch）用新建空目录关闭钩子及子模块自动执行；新版与本地被忽略文件路径冲突时也停止覆盖。个人配置在技能目录外，不参与更新。

| 状态 | 处理 |
| --- | --- |
| `current` | 实际联网，提交相同，可继续 |
| `updated` | 已备份并快进，先重新读取入口和所需参考后继续 |
| `update-available` | 仅 `--check-only` 才返回；不能把“发现”说成“已更新” |
| `not-managed` | 无接口安装记录且不是独立Git仓库，按README完整安装；保留旧文件 |
| `blocked` | 来源不一致、分支错误、本地修改/未跟踪文件、分叉或新版本链接等异常，保留原状并解决，不强制拉取 |
| `unavailable` | Git/网络/文件操作未成功，不能确认新版；先排查一次。仍失败时只读整理，业务写入需用户明确同意本次离线继续 |

可只读检查 `git status --short`、`git remote -v`、`git log`。不打印包含凭据的地址。不为解锁更新自动执行 `reset --hard`、`clean`、删目录、强制切分支或重写远端；本地个性规则移到外部配置，其他本地修改要先备份比较，必要时请使用者决定采用哪份。

同名目录首次迁移：先完整备份旧目录，准备并验证接口安装或独立克隆，确认文件完整和个人配置迁移后再切换。旧副本放技能发现目录之外保留，避免两个同名技能同时触发。不是直接把新仓库覆盖到旧目录。

更新不是沙箱或签名验证：仅信任使用者安装时确认的这个维护源。它不会运行新版脚本，但新版规则仍需重新读入并遵守宿主权限；新版内容不产生邮箱、发票上传、审批提交或实际支付的额外授权。

维护者发布：在独立开发副本修改和测试，提交必要文件并正常推送main，不强推。Git主站暂时不可达时可用GitHub官方Git数据API基于当前远端提交创建后续提交并更新引用，禁止强制更新，拒绝混入开发副本无关文件。校验格式、更新脚本、脱敏模板及公开隐私；成功发布后回读远端提交与可见性。可创建对应版本Tag/Release，不能把本地保存当已发布。使用者自动更新跟随main而非下载页或旧压缩包。
